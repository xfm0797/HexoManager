## 交付：中英双语界面（v1.2.0）

### 架构决策：**中文原文即词条**，不引入 i18n 框架

源码保留中文原文，只用 `t('文章管理')` 包一层；`src/i18n/locales/en-US.ts` 是
`Record<string, string>`，**键就是中文原文**。命中查表、未命中回退中文
（永不显示 key、永不抛错）。理由：中文是唯一表述源，不必维护 key 命名与两份文案结构。

- `src/i18n/index.ts`：`t()` / `useI18n()` / `getLocale()` / `isZh()` /
  `detectSystemLocale()` / `LOCALE_OPTIONS` / `LOCALE_STORAGE_KEY`
- **语言解析**：显式偏好（`localStorage` 键 `hexo-manager:locale`，值 `system|zh-CN|en-US`）
  > 系统语言。`navigator.language` + `navigator.languages` 里第一个非空者，
  以 `zh` 开头 → `zh-CN`，**其余一切（含 `en`/`C`/`POSIX`/空）→ `en-US`**
- 切语言副作用：`dayjs.locale()`、`document.documentElement.lang`、
  AntD `ConfigProvider locale`（`App.tsx`）、`document.title`
- 插值：`{name}` 占位符，如 `t('共 {count} 篇', { count: n })`
- **`useI18n()` 返回的 `t` 用 `useCallback` 按 `locale` 固化身份**（内部走
  `translateIn(locale, …)`）。这样把它写进 `useMemo`/`useCallback` 依赖数组
  既符合 `react-hooks/exhaustive-deps`（不再是「外部作用域的值」），
  又能在切语言时真正重算。**这是本项目 i18n 的关键设计点**
- 数字/时长按语言分叉：`formatCompactNumber` 走 `万/亿` 或 `K/M/B`；
  `formatDuration` 走 `${m} 分 ${s} 秒` 或 `${m}m ${s}s`

### 后端错误：前端映射层，不改 Rust 签名

Rust 侧 250+ 条中文错误统一是 `Result<T, String>`，改错误码会牵动 60+ 个命令签名，
故新增过渡层 `src/i18n/backendMessages.ts`：`EXACT` 精确表 + `RULES` 带参正则表，
由 `services/invoke.ts` 在 catch 中调用 `translateBackendMessage()`。
中文环境直接返回；未命中则原样返回中文（绝不吞信息）。

### 工具链：两个无依赖 Node 脚本

- `scripts/i18n-merge.mjs`：**增量 + 幂等**合并 `src/i18n/locales/_parts/*.json`
  到 `en-US.ts`。先读回现有字典（含 `unescapeJs`）再用零件覆盖，避免覆盖手工修正；
  合并后清空 `_parts`（`--keep` 可保留）
- `scripts/i18n-coverage.mjs`：报告词条数 / 字典数 / 缺译文 / **译文残留中文** / 未转换中文行；
  缺译文或译文含 CJK 时**退出码 1**。已接入 CI 的 check job
- npm 脚本：`npm run i18n:merge` / `npm run i18n:check`

### 覆盖率结果

1356 条 `t()` 词条 / 1465 条字典，**缺译文 0、译文残留中文 0**（唯一豁免是
语言选项里有意保留的母语自称「简体中文」，在脚本里以 `ALLOW_CJK_IN_TRANSLATION` 白名单化）。

## 排查与修复记录（踩坑）

1. **覆盖率脚本读出「4 条缺译文」是假阳性** —— 两个独立 bug：
   - `readDictKeys()` 对**带引号的键也做了 `.trim()`**，把 `" · 领先 {count}"` 读成
     `· 领先 {count}`，与源码词条不等
   - 源码端转义还原不完整（只还原 `\'` `\"` `\n`，漏了 `\\`），
     于是 `t('…D:\\blog…')` 与字典键对不上
   修法：带引号的键不 trim（只有裸键才 trim）+ 两端共用单趟扫描的 `unescapeJs()`
2. **解析器曾把文件头 `export const EN_US: Record<...>` 里的 `:` 当成键**，
   导致字典条目数虚高 1（1466 vs 实为 1465）。新正则要求 `:` 后必须跟带引号的值，已修正
3. **`src/i18n/backendMessages.ts` 有 8 个键是非法 JS**：纯中文裸键在 JS 里其实是合法标识符
   （CJK 属于 ID_Start），但只要键里含 `，`、空格或全角括号就语法错误。
   已把 `EXACT` 全表统一加引号，避免这类陷阱
4. **两条 EXACT 键与 Rust 原文不符**（`站点尚未安装依赖，请先执行 npm install`、
   `无法获取预览进程 PID` 各少一个空格），英文映射恒不生效。已修正
5. **`react-hooks/exhaustive-deps` 让 `npm run lint`（`--max-warnings 0`）失败**：
   - 7 个 hook 文件里 `t` 是模块级导入，写进依赖数组会被判「外部作用域的值」→ 从依赖数组移除
   - `Sidebar.tsx` / `ConfigPage.tsx` / `PluginsPage.tsx` 里的 `locale` 依赖 → 改为依赖
     `useI18n()` 的 `t`（见上文设计点），语义等价且合法
6. **4 处失效的 `eslint-disable-next-line no-await-in-loop`** 是历史残留
   （该规则在 `.eslintrc.cjs` 里根本没启用），`--report-unused-disable-directives`
   会直接报 error。已删除。注意 CI 里 lint 那步是 `continue-on-error: true`，所以一直没拦住
7. **CI 的 `lint` 是 `continue-on-error: true`** —— 别以为 lint 过了就代表 CI 全绿
8. **`git push` 之前卡住的原因不是凭证失效，而是交互式提示**：
   加 `GIT_TERMINAL_PROMPT=0` + `timeout` 后 push 与 `ls-remote` 都正常
9. Windows 上 `node -e` 里正则/反斜杠转义会被 shell 吃掉 → 一律改写临时 `.mjs` 脚本执行，
   用完删除（避免污染仓库）
