## 全量代码评审（v1.2.0 @ 729515c）

产出 `docs/architecture-review-2026-11-14.md`：架构分层、11 张表的关系、6 条核心流程、
20 项问题（P0/P1/P2/P3）与 3 个迭代的落地清单。

核心结论（后续动手前先看这几条）：

- **P0-1 语义错配**：`article_commands::sync_articles` 是「全量对账」（未出现的 file_path 会被 DELETE），
  但 create/update 只传单篇 → 每次保存会删掉同站其他文章行。后果：ID 漂移、手动保存后
  `fetchTaxonomies` 读到的分类/标签只剩当前这篇。修复方向：拆 `upsert_article` + `reconcile_site`。
- **P0-2**：`publish_article_impl` 写 `_posts/<file_name>` 前不检查已存在 → 同名草稿发布会静默覆盖线上文章。
- **P0-3**：主题配置读优先 `themes/<t>/_config.yml`、写也只写它，而 Hexo 的覆盖文件
  `_config.<t>.yml` 永远读不到 → 用覆盖模式的用户「改了没效果」。
- **P1-1 性能天花板**：`get_articles` / `get_site_stats` 每次调用都 `rescan_articles`（遍历全部 md + 逐行 UPDATE），
  且 `ARTICLE_COLUMNS` 含 `content`（与注释"列表不返回全文"相反）。
- **P1-2**：`config_generator` 里 platform=="edge" 的 4 个模板永不满足 include 条件
  （前端 `ciPlatforms` 只传 7 个 Pages 平台）→ 「启用边缘层」生成空结果；
  且 github/gitee/gitlab/cloudflare 四个 workflow 模板硬编码 `npm install`+`npx hexo generate`，忽略 `build_command`。
- **P1-3**：`main.tsx` 直接 import `utils/monaco`，`import * as monaco` 拉全语言包 → dist 16MB
  （ts.worker 6.8M + monaco 3.9M）。改为只引 markdown/yaml/json 贡献 + 懒加载可降到 ~4MB。
- **P1-4**：后端 13 处 `emit`，前端 `listen(` 0 处；`process::run_streaming` 死代码 → 构建/部署无实时日志。
- **P1-5**：`serde_json` 未开 `preserve_order` + 每次保存都写 `updated` → front matter 键序按字母重排、注释丢失，
  每次保存一次全量 diff（"基于 git 的历史版本"功能因此失真）。
- **P2**：时间口径混用（库 UTC / front matter Local / 排序混拼）；预览服务 `mem::forget` 且退出不清理（孤儿 node 进程）；
  `theme_configs`、`plugins` 只写不读；schema 无 `user_version`；`file_commands` 无路径白名单；
  手动装包不验签（pubkey 与 plugin-updater 都配了却没用）。
- **P3**：CI 没有 `cargo test`（约 20 个已有测试从未执行），lint/clippy/fmt 全 `continue-on-error`。

已核对：`tsc --noEmit` 与 `eslint --max-warnings 0` 均 0 报错；7 文件 8 处版本号均为 1.2.0（一致）。
未使用依赖：`isomorphic-git`、`@ant-design/charts`、`@tauri-apps/plugin-fs/process/updater`。

## 迭代 3 落地（同日）

### 预览服务生命周期（P2-2，`hexo/server.rs` 整体重写）
- `ServerRegistry(Mutex<HashMap<i64, RunningServer>>)`，`RunningServer { info, child: tokio::process::Child, log_tail }`，
  提供 `list/get/insert/stop_by_pid/stop_site/stop_all/len`。淘汰判据是 `child.try_wait()` 而非 `kill(pid,0)`。
- **两个必踩的坑**：① 子进程 stdout/stderr 必须用后台线程常驻读取并写入容量 200 的环形缓冲，
  否则管道写满 64KB 时 hexo 自己会阻塞；② 启动失败时必须回传最近 12 行输出，否则用户只看到"超时"。

  `RunEvent::ExitRequested{..} | RunEvent::Exit` 调 `state.servers.stop_all()`。**`app` 变量不能省**，否则闭包捕获不到。

## 首次 push 与 CI 首跑 `cargo test`（2026-11-14 夜）

**推送通道**：`origin` 是 HTTPS，但本机没有存 GitHub 凭据（`cmdkey /list` 无 github 项），
Git 凭据管理器在非交互环境弹窗被取消 → `fatal: could not read Username`。
`~/.ssh/id_ed25519` 可用（`ssh -T git@github.com` 返回 `Hi xfm0797!`），
因此用 `git push git@github.com:xfm0797/HexoManager.git main` 推送，**没改 remote 配置**；
之后 `git fetch origin` 同步 `origin/main` 跟踪引用。

**CI 首次真正跑起 `cargo test`**（`.github/workflows/build.yml` 的 check job）：
50 passed / 2 failed，全部集中在 `local_time_to_utc` 的 `Z` 后缀。

> **chrono 坑（重要）**：`%:z` 只匹配 `+08:00`（带冒号），**不认 `Z`**；
> `%Z` 匹配的是时区**名称**（`UTC`/`GMT`），也不认 `Z`。
> 解析带 `Z` 的 RFC 3339 必须用 `DateTime::parse_from_rfc3339`（`Z` 与 `+08:00` 都吃，
> 空格分隔也吃），而它对 `+0800`（无冒号）返回 Err —— 两者覆盖范围互补，
> 正确顺序是「rfc3339 → `%:z`/`%z` 等非标写法 → 裸时间按本地解释 → 纯日期」。

**只读 API 拿不到日志**：`/actions/jobs/{id}/logs` 与 `/actions/runs/{id}/logs` 需要认证
（403）；check-run 的 `annotations` 是公开的，但失败步骤只给
`Process completed with exit code 101`（Rust panic/断言失败的通用码）。

**本机跑不了 `cargo test` 的代价**：所有 Rust 断言直到 CI 才第一次执行，
新写的测试有没有错无从得知 —— 因此新增测试后**必须确认 CI 绿**，不能只看 `cargo check`
（`--all-targets` 只保证测试代码能编译，不保证断言成立）。
