# 2026-11-15

## 迭代 5：P3-3 后端错误码化（全模块）

评审报告里最后一项长期项。根因不是「映射表写得不好」，而是**错误里只有人类可读文本、
没有机器可读标识**，所以 Rust 侧改一个字，前端按文本匹配的译文就静默失效。

### 做法

1. `utils/error.rs`：新增 `AppError::Coded { code, message, params }`。
   - `Serialize` 从字符串改为 `{ code, message, params }` 对象；
   - `Display` **仍是中文原文** —— 这条很关键，未迁移路径的 `.map_err(|e| e.to_string())`
     输出一字不变，才敢分批迁移；
   - `code()` 给粗粒度变体（`db` / `io` / `not_found` / `forbidden` …）兜底码，
     `message()` 给中文原文，`params()` 给占位值（静态空表避免每次分配）。
2. 全部命令签名 `Result<T, String>` → `AppResult<T>`，`blocking::cmd` → `blocking::run`，
   删掉约 150 处 `map_err(|e| e.to_string())`。
3. `format!` 形态的临时错误统一用已有的 `err!` 宏（`Err(format!(` → `Err(err!(` 是纯文本
   替换，括号天然平衡，比手改 80 处安全）。
4. 17 个语义码，译文在 `src/i18n/errorCodes.ts`，`{name}` 占位符由 params 填充：
   `site.not_found|path_empty|path_taken|already_imported|path_missing|dir_missing|not_hexo|target_exists`、
   `article.not_found|file_missing|filename_invalid|reload_failed`、
   `path.empty|root_forbidden|outside_site`、`git.show_failed|commit_read_failed`。
5. `scripts/error-codes-check.mjs` 静态比对 Rust `coded("…")` 与字典条目（缺失 / 译文含中文
   → 退出码 1），并入 `npm run i18n:check`，CI 步骤改成跑 `npm run i18n:check`。

### 踩到的坑

- **`AppError` 的 `Serialize` 一改，所有返回 `AppResult` 的命令都变成对象 rejection** ——
  前端 `errorMessage(error)` 取 `error.message` 仍能拿到中文，所以旧文本映射继续生效，
  这是「不写前端也能先跑」的原因；但必须先确认前端有对象分支，否则会显示 `[object Object]`。
- `blocking::cmd` 的闭包返回 `Result<T, String>`，命令改 AppResult 后会类型不匹配；
  改 `blocking::run` + 闭包里 `err!`/`coded` 即可。
- `rows.collect::<Result<Vec<_>, _>>()` 这类原来靠 `.map_err(|e| e.to_string())` 收尾的表达式，
  删掉 map_err 后错误类型变回 `rusqlite::Error`，需要 `.map_err(AppError::from)`。
- `serde_json::to_string_pretty(...)` 同理，直接 `Ok(...?)` 更短。
- 批量替换会产生重复 `use crate::err;`（脚本两次插入），编译器会报 E0252，肉眼扫一眼导入块即可。

## 收尾：Rust 格式统一 + clippy 清零

**工具链**：本机此前没装 rustfmt / clippy（`rustup component add` 直连超时）。
用国内镜像装成功，值得记住：

```bash
export RUSTUP_DIST_SERVER=https://rsproxy.cn RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup
rustup component add rustfmt clippy
```

**clippy 6 条真实告警**（`hexo-manager` 本体，不含 schemars 补丁 crate 的 3 条 cfg 告警）：
复杂返回类型 → 抽 `type FileFingerprints`；`ServerRegistry` 有 `len` 无 `is_empty` → 补上；
`Command::new(&npx_bin)` 与 `&npx()` 多一层借用；`install.rs` 的 `return Ok(())` 改块尾值；
`hexo_commands.rs` 一处游离 doc 注释（描述的函数早已不存在，注释挂到了 `use` 上）。

**fmt**：`cargo fmt` 动 21 个文件、净减 76 行，CI 的 `cargo fmt --check` 顺带从
`continue-on-error` 改成硬卡口。clippy 的 `-- -D warnings` 保留 `continue-on-error` ——
clippy 会随工具链新增 lint，硬卡会让「升级 stable」变成发布阻塞。

**注意**：本地跑 `cargo clippy -- -D warnings` 会因 schemars 补丁 crate 的 cfg 告警失败；
CI 没有那个补丁，所以本地只能用不带 `-D warnings` 的版本确认「本 crate 0 告警」。

## 迭代 6：P3-3 收官 —— 删掉 backendMessages.ts

上一轮只做了 article / site 两个模块（17 个码），其余模块靠两张表按**中文原文**匹配。
这一轮把剩下的中文错误全部改成语义码，并把过渡层整体删除。

### 规模

- **41 处 `err!`** + **约 90 处中文字面量直入原始变体**（`AppError::Other("…")` 26 处、
  `Err("…".into())` 13 处、`map_err(|_| format!("…"))` 与 `ok_or_else(|| "…")` 若干）
- 语义码 **17 → 111 个**，字典条目 123（含 12 个通用码）
- 覆盖 config / file / template / theme / deploy / update / git / hexo / preview / proc / db / link

### 关键设计：通用码 + `{detail}` 透传

粗粒度变体（`Io` / `Json` / `Process` / `Template` …）的正文来自 OS 或第三方库，**本来就翻不了**。
所以 `params()` 为它们统一返回 `{ detail: 内部文本 }`，译文模板写成 `I/O error: {detail}`，
只翻前缀。这样 40 多处「包一层外部错误」的地方一行都不用改，直接吃变体自带的通用码。

判断标准写进 `utils/error.rs` 的模块注释：**消息里有自己写的中文措辞 → 必须 `coded`**。

### 删掉的三个「捷径」

- `err!` 宏：让「写错误时忘了给码」成为默认行为
- `blocking::cmd`：字符串错误通道，已无调用方
- `impl From<String> / From<&str> for AppError`：字符串进不来，`Err("中文".into())` 直接编译失败

移除 `From<String>` 后 `cargo check` 一次通过（说明真的没有遗漏的字符串错误通道）。

### 检查脚本扩为 6 条规则（`scripts/error-codes-check.mjs`）

1. Rust 用到的 code 必须在字典里；
2. 译文不许残留中文；
3. 语义码必须 `<模块>.<语义>`（带点），通用码必须**恰好**等于 `AppError::code()` 的返回集合
   （靠正则抽 `AppError::X(_) => "code"` 比对，新增变体忘配译文即失败）；
4. 禁止 `err!`；
5. 禁止中文字面量直入原始变体，4 条正则覆盖 `AppError::X("…")` / `Err("…".into())` /
   `map_err(...format!("…"))` / `ok_or_else(|| "…")`，`#[cfg(test)] mod` 之后的内容自动跳过；
6. 孤儿条目只提示不失败。

**豁免机制**：命中行或上方 3 行内有 `// error-codes-check: skip` 才跳过 —— 目前只有
`lib.rs` 的 setup 期数据库初始化用过（那条错误没有前端通道）。

### 踩到的坑

- 字典键写成 `io: '…'` 这种**裸标识符**时，脚本的 `'([a-z0-9_.]+)'` 正则匹配不到，
  表现为「通用 0 个」→ 通用码统一加引号。
- `theme_commands` 里同一个中文串出现两处（`必须提供 config 或 raw`），批量替换只改到一处，
  靠检查脚本的「无码中文错误」规则才捞出来。
- `theme_name` 拼接在句尾的提示（`{}（主题名：{}，站点路径：{}）`）无法直接码化 ——
  改成结构化参数让译文自己组织语序，顺带删掉冗余的站点路径。
- `preview.listen_timeout` 的 hint 原本是中文句子或「最近输出：…」两种形态：
  拆成 `listen_timeout` / `listen_timeout_no_output` 两个码，后者才带 `npm install` 建议。
- 列表分隔符 `join("、")` 换成 `join(", ")`：`{list}` 参数会被原样塞进英文句子。

### 仍未解除的中文

`check_hexo_env` 的 `issues`、更新清单的 `清单格式无法识别`、`未命名站点` 等是**数据**，
不经 `invoke` 的 catch，因此从来没走过文本映射表；要英化需改成结构化 UI 文案载荷，
与错误码是两套机制。已写进评审文档的「遗留」段。
